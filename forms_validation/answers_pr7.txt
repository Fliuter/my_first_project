Ответы на вопросы для самоконтроля — ПР №7

1. Какие HTML5-атрибуты используются для клиентской валидации и какую функциональность они предоставляют?
Для проверки данных применяются required, type, minlength, maxlength, min, max, step и pattern. required делает поле обязательным, type проверяет формат данных (например, email), minlength и maxlength задают длину текста, min и max — допустимый диапазон чисел или дат, step — шаг значения, pattern — проверку по регулярному выражению.

2. В чем разница между novalidate атрибутом формы и отключением валидации через JavaScript?
Атрибут novalidate отключает встроенную браузерную проверку при отправке конкретной формы. Отключение или изменение проверки через JavaScript выполняется программно, например с помощью form.noValidate или setCustomValidity(). При novalidate разработчик должен самостоятельно выполнить нужную проверку в обработчике submit.

3. Как правильно связать <label> с полем ввода и почему это важно для доступности?
Нужно указать у label атрибут for со значением, совпадающим с id поля: <label for="email">Почта</label> и <input id="email">. Тогда нажатие на подпись переводит фокус в поле, а скринридер может корректно озвучить назначение элемента.

4. Какие типы полей input наиболее подходят для разных видов данных (email, телефон, пароль и т.д.)?
Для электронной почты используют type="email", для телефона — type="tel", для пароля — type="password", для чисел — type="number", для даты — type="date", для ссылки — type="url", для обычного текста — type="text". Правильный тип упрощает ввод и может включать подходящую проверку браузера.

5. Как работает валидация с помощью pattern атрибута и в каких случаях его следует использовать?
pattern задаёт регулярное выражение, которому должно соответствовать значение поля. Его используют, когда стандартной проверки типа недостаточно, например для формата номера телефона или почтового индекса. pattern следует применять только для понятного и обоснованного формата, не ограничивая пользователя без необходимости.

6. Какие события JavaScript используются для реализации валидации в реальном времени и почему?
Чаще всего используют input, change, blur и submit. input срабатывает при изменении значения и позволяет проверять его во время ввода; change — после подтверждённого изменения; blur — когда пользователь покидает поле; submit — при отправке всей формы. Это помогает показывать ошибки своевременно.

7. Как обеспечить доступность сообщений об ошибках для пользователей скринридеров?
Сообщение об ошибке нужно связать с полем через aria-describedby, а для динамического сообщения использовать aria-live="polite". При ошибке можно установить aria-invalid="true". Текст ошибки должен ясно объяснять, что именно нужно исправить.

8. В чем преимущества использования fieldset и legend для группировки полей формы?
fieldset объединяет связанные поля в одну группу, а legend задаёт название этой группы. Это улучшает структуру формы и помогает пользователям скринридеров понять, к какой общей категории относятся поля, например к данным пароля.

9. Как реализовать кастомную валидацию для сложных случаев (например, подтверждение пароля)?
Нужно получить значения полей через JavaScript и сравнить их. Если пароль и подтверждение не совпадают, показать сообщение об ошибке, установить aria-invalid и не отправлять форму. При необходимости можно использовать метод setCustomValidity() для задания собственного текста ошибки.

10. Какие методы CSS используются для визуального отображения состояний валидности/невалидности полей?
Можно использовать псевдоклассы :valid и :invalid, классы valid и invalid, а также менять border-color, background-color и outline. В этой работе для наглядности JavaScript добавляет класс valid или invalid, а CSS задаёт соответствующее оформление.
