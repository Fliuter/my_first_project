Ответы на вопросы для самоконтроля

1. Какие три основные области работы с файлами в Git и чем они отличаются?

Рабочая папка — место, где находятся и изменяются файлы проекта.

Индекс — область, в которую добавляются изменения перед коммитом.

Репозиторий — место, где хранятся сохранённые версии проекта и история коммитов.

2. Что происходит при выполнении команд git add, git commit, git push?

git add — добавляет изменения в индекс.

git commit — сохраняет изменения в истории репозитория.

git push — отправляет коммиты в удалённый репозиторий.

3. Почему важно писать информативные сообщения к коммитам?

Чтобы было понятно, какие изменения были сделаны и для чего. Это упрощает просмотр истории проекта.

4. Чем отличается git add имя_файла от git add .?

git add имя_файла добавляет конкретный файл.

git add . добавляет все изменения в текущей папке и её вложенных папках.

Первую команду удобно использовать для одного файла, вторую — для нескольких изменений.

5. Что показывает команда git status?

Она показывает состояние файлов проекта: какие файлы изменены, какие добавлены в индекс и какие ещё не отслеживаются Git.

6. Для чего нужна команда git remote add origin URL и что означает origin?

Она связывает локальный репозиторий с удалённым репозиторием. Origin — стандартное имя удалённого репозитория.

7. Зачем нужен флаг -u в команде git push -u origin main?

Он устанавливает связь между локальной веткой main и удалённой веткой origin/main. При следующих отправках можно использовать git push без дополнительных параметров.

8. Что такое ветка по умолчанию и какая создалась у вас? Почему это важно?

Ветка — отдельная линия разработки проекта. Изначально у меня создалась ветка master, затем я переименовал её в main. Это важно для правильной работы с удалённым репозиторием.

9. Как просмотреть историю коммитов и какую информацию о каждом коммите вы видите?

Историю можно посмотреть командой git log или git log --oneline. Отображаются идентификатор коммита, автор, дата и сообщение коммита. В сокращённом режиме выводится краткая информация.

10. Что произойдёт, если сделать изменения в файле, но не выполнить git add перед git commit?

Изменения не попадут в новый коммит, потому что они не добавлены в индекс. Git сохранит только те изменения, которые подготовлены командой git add.
