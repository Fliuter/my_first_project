# Ответы на вопросы для самоконтроля — ПР №14

1. **Fetch API и XMLHttpRequest.** Fetch — современный Promise-based интерфейс, удобный для async/await, проще комбинируется с Promise.all и поддерживает потоки. XMLHttpRequest старше, работает через события и имеет встроенное отслеживание прогресса загрузки/отправки. Fetch обычно удобнее для новых приложений.

2. **Обработка ошибок.** Fetch отклоняет Promise при сетевой ошибке, ошибке CORS или отмене запроса, но не при HTTP 404/500. Поэтому после получения Response нужно проверить `response.ok` или `response.status` и самостоятельно выбросить ошибку.

3. **HTTP-методы.** GET получает данные; POST создаёт ресурс или запускает операцию; PUT полностью заменяет ресурс; PATCH изменяет часть ресурса; DELETE удаляет ресурс; HEAD получает только заголовки; OPTIONS узнаёт доступные параметры взаимодействия.

4. **Заголовки.** Их передают через `headers` в параметрах fetch или объект `Headers`. Примеры: `Content-Type` описывает формат тела, `Accept` — желаемый формат ответа, `Authorization` — данные авторизации, `Cache-Control` — правила кэширования. Заголовки ответа доступны через `response.headers`.

5. **PUT и PATCH.** PUT обычно передаёт полное новое представление ресурса. PATCH передаёт только изменяемые поля. PATCH удобен для небольших частичных изменений, PUT — для полной замены.

6. **Авторизация.** Basic Auth передаёт имя и пароль в заголовке Authorization в кодировке Base64 (только по HTTPS). Bearer Token передаёт токен как `Authorization: Bearer ...`. OAuth2 — протокол получения ограниченных токенов доступа; приложение получает токен через предусмотренный поток и передаёт его в запросах. Секреты нельзя хранить в открытом клиентском JavaScript.

7. **Отмена запросов.** Основной способ — `AbortController`: его `signal` передают в fetch, а затем вызывают `controller.abort()`. Это полезно при таймаутах, уходе со страницы или изменении поискового запроса. `AbortSignal.timeout()` позволяет задать таймаут в поддерживающих его браузерах.

8. **Форматы данных.** JSON читают через `response.json()` и отправляют через `JSON.stringify`. FormData используют для полей формы и файлов; вручную задавать Content-Type для multipart не нужно. Blob подходит для файлов и изображений, ArrayBuffer — для низкоуровневой работы с бинарными данными.

9. **Производительность.** Независимые запросы можно запускать параллельно через `Promise.all`; для независимых операций, где допустимы частичные ошибки, подходит `Promise.allSettled`. Повторные одинаковые GET-запросы можно кэшировать с TTL. Также полезны пагинация, отмена устаревших запросов и ограничение числа одновременных запросов.

10. **Production-практики.** Проверять `response.ok`, обрабатывать сетевые и HTTP-ошибки, задавать таймауты и отмену, не хранить секреты в клиентском коде, использовать HTTPS, валидировать входные данные, не выводить непроверенный HTML, ограничивать повторы и применять задержку между ними, логировать ошибки и тестировать крайние случаи.
