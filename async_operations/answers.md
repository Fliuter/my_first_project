Ответы на вопросы для самоконтроля — ПР №13

1. В чем разница между Promise.then().catch() и async/await с try/catch? Когда следует использовать каждый подход?
.then() и .catch() обрабатывают результат промиса цепочкой методов. async/await позволяет записывать асинхронный код в более привычном последовательном виде, а ошибки перехватывать через try/catch. then/catch удобны для коротких цепочек и функционального стиля. async/await обычно удобнее для нескольких последовательных операций и сложной логики.

2. Как работает Promise.all и что происходит, если один из промисов в массиве завершается ошибкой?
Promise.all запускает переданные промисы параллельно и возвращает один промис с массивом результатов в исходном порядке. Он успешно завершается, когда успешно завершились все промисы. Если хотя бы один промис отклоняется, общий Promise.all отклоняется с первой полученной ошибкой. Остальные операции автоматически не отменяются.

3. В чем разница между Promise.all, Promise.race и Promise.allSettled? Приведите практические примеры использования каждого.
Promise.all ждёт успешного выполнения всех операций — например, загрузки нескольких частей страницы. Promise.race возвращает результат первого завершившегося промиса — например, для ограничения времени ожидания ответа. Promise.allSettled ждёт завершения всех операций независимо от результата — например, когда нужно получить отчёт об успешных и неуспешных загрузках.

4. Как реализовать повторные попытки (retry logic) для асинхронных операций с экспоненциальной задержкой?
Операцию помещают в цикл или рекурсивную функцию с try/catch. При ошибке выполняют повтор, но перед ним ждут всё дольше: например, 250, 500, 1000 и 2000 миллисекунд. Задержка вычисляется как начальная задержка, умноженная на 2 в степени номера попытки. После достижения лимита попыток ошибку возвращают вызывающему коду.

5. Что такое «состояние гонки» (race condition) в асинхронном коде и как его избежать?
Состояние гонки возникает, когда несколько асинхронных операций обращаются к общим данным, а итог зависит от порядка их завершения. Например, два запроса обновляют один элемент интерфейса, и более старый ответ приходит позже нового. Избежать проблемы помогают последовательное выполнение, блокировки, отмена устаревших запросов через AbortController, проверка идентификатора последнего запроса и аккуратное управление общим состоянием.

6. Как работает кэширование результатов асинхронных запросов и какие стратегии кэширования существуют?
При первом запросе результат сохраняется в хранилище, например Map, под ключом URL или параметров. При повторном запросе данные возвращаются из кэша без нового обращения к серверу. Используются кэширование на заданное время (TTL), кэширование до ручной очистки, стратегия stale-while-revalidate, а также ограниченный кэш с удалением давно неиспользуемых записей. Важно удалять из кэша неудачные запросы и учитывать актуальность данных.

7. Какие методы оптимизации производительности можно применить при работе с множественными асинхронными операциями?
Независимые запросы следует запускать параллельно, например через Promise.all. Для большого количества задач полезно ограничивать число одновременных запросов. Также применяют кэширование, пакетную загрузку, отмену ненужных запросов, повторное использование соединений и минимизацию объёма передаваемых данных. Последовательное выполнение используют только там, где следующая операция зависит от предыдущей.

8. Как обрабатывать ошибки в цепочках промисов и предотвращать «проглатывание» ошибок?
Нужно добавлять .catch() в цепочку или использовать try/catch внутри async-функций. Ошибку нельзя просто игнорировать: её следует вывести, записать в журнал или передать выше через throw. Если внутри catch ошибка обработана частично, важно явно вернуть результат или повторно выбросить ошибку. Также следует проверять HTTP-статус ответа fetch, потому что HTTP 404 сам по себе не отклоняет промис fetch.

9. В чем преимущества использования async/await по сравнению с традиционными промисами и обратными вызовами?
async/await делает последовательность асинхронных действий более читаемой, уменьшает вложенность, упрощает обработку ошибок через try/catch и облегчает отладку. По сравнению с callback-подходом код не превращается в глубокую вложенность функций. При этом async/await работает на основе промисов и не делает операции автоматически параллельными.

10. Как отлаживать асинхронный код и какие инструменты разработчика наиболее полезны для этого?
В браузере можно использовать DevTools: вкладку Console для ошибок и логов, Sources для точек останова и пошагового выполнения, Network для проверки запросов и ответов API, Performance для анализа времени выполнения. Полезны console.log(), debugger, обработка rejected-промисов и проверка сетевых ошибок. Для воспроизводимости ошибок следует проверять разные задержки, неуспешные ответы и крайние случаи.
