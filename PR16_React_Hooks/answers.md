# Ответы на вопросы для самоконтроля — ПР №16

1. **В чем разница между useState и useReducer? Когда использовать каждый?**
   `useState` подходит для простого состояния: строки, числа, флаги и небольшие объекты. `useReducer` удобен для сложного состояния, когда есть несколько типов действий и переходы состояния лучше описать в одной функции-reducer.

2. **Как работает массив зависимостей в useEffect? Что произойдет если его не указать?**
   React повторно запускает эффект после рендера, если изменилось хотя бы одно значение из массива зависимостей. Пустой массив `[]` означает запуск после монтирования (и очистку при размонтировании). Если массив не указать, эффект выполняется после каждого рендера.

3. **Что такое stale closure в хуках и как использовать функциональные обновления?**
   Это ситуация, когда функция использует значения состояния из старого рендера. Функциональное обновление, например `setCount(prev => prev + 1)`, получает актуальное предыдущее значение и помогает избежать ошибки.

4. **Когда действительно нужны useCallback и useMemo? Не являются ли они преждевременной оптимизацией?**
   `useMemo` кэширует результат вычисления, а `useCallback` — ссылку на функцию. Они полезны при дорогих вычислениях, передаче функций или значений в мемоизированные компоненты и при стабильных зависимостях. Без измеримой проблемы применять их повсюду не нужно.

5. **Как useRef отличается от useState? В каких сценариях useRef незаменим?**
   Изменение `useState` вызывает повторный рендер, а изменение `useRef.current` — нет. `useRef` используют для доступа к DOM-элементам, хранения таймеров и значений между рендерами, которые не должны напрямую обновлять интерфейс.

6. **Какие правила хуков существуют и почему их нельзя нарушать?**
   Хуки вызывают только на верхнем уровне функционального компонента или другого хука, не внутри условий, циклов и вложенных функций. Компоненты React вызываются как JSX-компоненты. Это позволяет React сохранять одинаковый порядок хуков между рендерами.

7. **Как создать кастомный хук и какие лучшие практики следует соблюдать?**
   Нужно создать функцию с именем, начинающимся на `use`, внутри использовать другие хуки и вернуть нужные данные или функции. Следует соблюдать правила хуков, делать одну понятную задачу, указывать зависимости эффектов и очищать подписки и таймеры.

8. **В чем преимущества использования useContext перед передачей props через несколько компонентов?**
   `useContext` позволяет получать общие данные из ближайшего Provider без передачи props через каждый промежуточный компонент. Это удобно для темы, языка, авторизации и других общих настроек.

9. **Как обрабатывать асинхронные операции в кастомных хуках?**
   Асинхронную функцию запускают внутри `useEffect` или обработчика события, а состояние загрузки, данных и ошибки хранят через `useState`. Нужно проверять `response.ok`, обрабатывать исключения и отменять запрос через `AbortController` при размонтировании или смене URL.

10. **Какие способы отладки хуков вы знаете?**
    Можно использовать React DevTools для просмотра компонентов и их props/state, консоль браузера и `console.log`, точки останова в DevTools, вкладку Network для запросов, а также тесты React Testing Library. Важно проверять зависимости эффектов и очищать таймеры и обработчики.
