# Ответы на вопросы для самоконтроля — ПР №12

1. **В чём разница между `event.preventDefault()` и `event.stopPropagation()`?**  
   `preventDefault()` отменяет стандартное действие браузера, например переход по ссылке или отправку формы. `stopPropagation()` прекращает дальнейшее распространение события по DOM-дереву. Первый метод используют, когда нужно обработать действие самостоятельно; второй — когда событие не должно доходить до других элементов-предков или потомков.

2. **Как работает делегирование событий и какие преимущества оно даёт?**  
   Обработчик назначается одному общему родительскому элементу. Когда событие всплывает от дочернего элемента, проверяется `event.target` или его ближайший подходящий родитель через `closest()`. Это уменьшает количество обработчиков и позволяет обрабатывать элементы, добавленные динамически после загрузки страницы.

3. **Какие фазы жизненного цикла события существуют?**  
   Существуют три фазы: capturing (погружение от документа к целевому элементу), target (непосредственно целевой элемент) и bubbling (всплытие от цели к родителям). По умолчанию `addEventListener()` обрабатывает событие на фазе всплытия. Для фазы погружения третьим аргументом можно передать `true` или `{ capture: true }`.

4. **В чём разница между `event.target` и `event.currentTarget`?**  
   `target` — элемент, на котором событие первоначально произошло. `currentTarget` — элемент, на котором сейчас выполняется обработчик. При делегировании `target` часто указывает на вложенную кнопку или текстовый элемент, а `currentTarget` — на общий родительский список.

5. **Как создать и запустить кастомное событие? Какие параметры передаются в `CustomEvent`?**  
   Событие создаётся через `new CustomEvent("имя", { detail: данные, bubbles: true, cancelable: true })`, а запускается методом `dispatchEvent()`. В `detail` можно передать любые данные, которые понадобятся обработчику. `bubbles` включает всплытие, а `cancelable` позволяет отменить действие события через `preventDefault()`.

6. **Что такое debounce и throttle? Где они применяются?**  
   Debounce откладывает выполнение функции до тех пор, пока поток вызовов не прекратится на заданное время. Он полезен для поиска по мере ввода текста и проверки формы. Throttle ограничивает частоту выполнения функции заданным интервалом. Его применяют при обработке прокрутки страницы, движения мыши и изменения размера окна.

7. **Какие методы существуют для удаления обработчиков событий и почему это важно?**  
   Обработчик удаляют методом `removeEventListener()` с тем же типом события, той же функцией и соответствующими настройками `capture`, которые использовались при добавлении. Также можно применять `AbortController` и передавать его `signal` в `addEventListener()`, а затем вызывать `abort()`. Удаление ненужных обработчиков предотвращает лишние вызовы, утечки памяти и ошибки при повторной инициализации компонентов.

8. **Как обрабатывать ошибки загрузки ресурсов?**  
   Для изображений, скриптов и других ресурсов используют событие `error`, которое возникает при неудачной загрузке. Для успешной загрузки изображения применяется `load`. В обработчике `error` можно показать сообщение, предложить повторить загрузку или установить запасное изображение. Для отслеживания состояния загрузки также используют доступные для конкретного API события и состояния.

9. **В чём разница между `addEventListener` и назначением через `onclick`, `onkeydown`?**  
   `addEventListener()` позволяет назначить несколько независимых обработчиков одного события, управлять фазой распространения и удалять обработчики через `removeEventListener()`. При присваивании `onclick` обычно хранится только один обработчик: новое присваивание заменяет предыдущее. Поэтому `addEventListener()` чаще удобнее и гибче.

10. **Как оптимизировать производительность при работе с большим количеством событий?**  
    Следует использовать делегирование событий, удалять ненужные обработчики, не выполнять тяжёлые вычисления внутри частых событий, применять debounce и throttle, а также избегать лишних изменений DOM. Для обработчиков, которые больше не нужны, можно использовать `removeEventListener()` или `AbortController`.
