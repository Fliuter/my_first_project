# Ответы на вопросы для самоконтроля — ПР №15

1. **В чём разница между функциональными и классовыми компонентами в React? Когда следует использовать каждый тип?**  
   Функциональные компоненты — это функции, которые возвращают JSX. Они используют хуки для состояния и побочных эффектов. Классовые компоненты объявляются через `class`, наследуются от `React.Component` и используют `this.state` и методы жизненного цикла. В новых проектах обычно выбирают функциональные компоненты, а классовые полезно знать для поддержки старого кода.

2. **Что такое props и state? Как они отличаются и какие правила их использования?**  
   `props` — входные данные, которые компонент получает от родителя; компонент не должен изменять их. `state` — внутреннее изменяемое состояние компонента. Его обновляют через `setState` в классе или функцию-сеттер из `useState` в функциональном компоненте.

3. **Как работает поднятие состояния (lifting state up) и в каких ситуациях это необходимо?**  
   Состояние переносят в ближайший общий родительский компонент, если нескольким дочерним компонентам нужны одни и те же данные. Родитель передаёт данные и функции изменения через props. Так компоненты используют единый источник данных.

4. **Какие методы жизненного цикла классовых компонентов вы знаете и для чего они используются?**  
   `componentDidMount` вызывается после первого появления компонента и подходит для запросов и подписок. `componentDidUpdate` вызывается после обновления и позволяет реагировать на изменение props или state. `componentWillUnmount` вызывается перед удалением и используется для очистки таймеров и обработчиков событий.

5. **Как работают хуки useState и useEffect? Какие правила использования хуков существуют?**  
   `useState` добавляет компоненту состояние и возвращает значение с функцией его обновления. `useEffect` выполняет побочные действия после рендера; функция очистки отменяет подписки и таймеры. Хуки вызывают только на верхнем уровне функционального компонента или собственного хука, не внутри условий, циклов и вложенных функций.

6. **Что такое ключи (keys) в React и почему они важны при рендеринге списков?**  
   `key` — уникальный идентификатор элемента списка. Он помогает React правильно сопоставлять элементы между рендерами, обновлять изменившиеся элементы и не путать их состояние. Лучше использовать стабильный ID, а не индекс массива.

7. **Как обрабатывать события в React и чем это отличается от нативного JavaScript?**  
   События задаются JSX-атрибутами в camelCase, например `onClick` или `onChange`, а обработчик передаётся как функция. В нативном JavaScript часто используют `addEventListener`. React предоставляет единый механизм обработки событий и автоматически управляет их привязкой к элементам.

8. **Что такое управляемые и неуправляемые компоненты? В чём их разница?**  
   В управляемом поле значение хранится в React state и обновляется через `onChange`. В неуправляемом поле значение хранится в DOM, а для чтения обычно используют `ref`. Управляемые элементы удобнее валидировать и синхронизировать с интерфейсом.

9. **Как работает контекст (Context) в React и когда его следует использовать?**  
   Context позволяет передавать данные через дерево компонентов без ручной передачи props на каждом уровне. Данные создают через `createContext`, предоставляют через Provider и читают через `useContext`. Подходит для темы оформления, языка или данных текущего пользователя.

10. **Какие преимущества предоставляют кастомные хуки и как создавать собственные хуки?**  
    Кастомные хуки позволяют повторно использовать логику состояния и эффектов в разных компонентах. Это обычные функции, имя которых начинается с `use`; внутри них можно вызывать другие хуки. Например, `useLocalStorage` синхронизирует состояние с хранилищем браузера, а `useFetch` выполняет HTTP-запрос.
